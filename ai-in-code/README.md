**От обычной функции до проверяемого AI-сервиса: 16 основных этапов с объяснениями, источниками, практикой и критериями готовности.** В этап 03 добавлен обязательный практикум 03A: context engineering и первые evals перед роутингом.

## Начните здесь

**Первое действие: [этап 00 — диагностика и запуск](modules/00-start.md).** Откройте [лабораторию](lab/README.md), запустите пример без API-ключа и проследите путь одного запроса. Затем двигайтесь по ссылке «Дальше» внизу каждой главы.

Уже строите такие системы? Откройте [итоговое задание](modules/15-capstone.md), покажите эквивалентный проект и проходите только выявленные пробелы. Читать весь курс ради допуска к разговору не требуется.

## Для кого и что нужно на входе

Для разработчиков, студентов и выпускников школ программирования, которые хотят встроить LLM в приложение. Нужны функции, базовые типы, ошибки, работа с файлами и умение запустить тест. Если этих навыков нет, этап 00 отправляет к базовым материалам по языку. Наш начальный курс общения с ИИ не заменяет программирование.

Основной учебный пример — Python, один язык достаточен. Для TypeScript, C#/.NET и Java есть [маршруты специализации](modules/14-specialization.md). Компьютер нужен для кода; с телефона можно читать. При отсутствии платного API выполните офлайн-части и явно отметьте непроверенную живую интеграцию. Покупать все инструменты или новое оборудование не требуется.

## Как проходить каждую главу

**Понять механизм → прочитать указанные разделы → повторить пример → сделать свою версию → сломать её контролируемым входом → проверить → объяснить → перейти дальше.**

В каждом этапе есть результат, материалы, последовательность действий, ошибки и самостоятельное изменение условия. Записывайте короткое доказательство по [WORKBOOK](WORKBOOK.md): версия кода, команда, результат, ограничение и объяснение. Статусы «прочитал», «повторил» и «умею самостоятельно» не равнозначны.

**Ключевая зависимость:** задача и критерии → первый вызов → контекст → небольшие evals → матрица качества → routing → оценка всей системы. Плохой контекст нельзя автоматически компенсировать более дорогой моделью; неизвестное качество не считается достаточным.

Номера — порядок зависимостей, не календарные даты. Двигайтесь по результату, а не по сроку. Для первого небольшого проекта сосредоточьтесь на 00–06, включая 03A, базовых тестах и безопасности; MCP, расширенный retrieval и специализацию добавляйте после понятного работающего ядра. Полный маршрут доводит до более широкого инженерного портфолио, а не обещает квалификацию за фиксированное число дней.

## Что вы строите

**Request Desk** — учебный сервис для вымышленного клуба. Он получает обращение, выбирает разрешённый обработчик, находит справку, считает обычным кодом и готовит подтверждённый ответ. Неизвестное остаётся неизвестным. Чужие данные не попадают в контекст. Лимит останавливает цикл. Запись и отправка не происходят без отдельного механизма разрешения.

Встроенная лаборатория демонстрирует **только офлайн-ядро**: ScriptedModel, два mock-маршрута, расчёт, lookup с tenant, проверку формата, лимиты и события. Сборщик контекста и реальная оценка моделей из 03A, HTTP, SDK, MCP, RAG и долговременная идемпотентность реализуются вами по заданиям. [Точный статус проверки](VALIDATION.md).
