# 00. Входная диагностика и первый запуск

[English](00-start.en.md) · [Карта пути](../README.md)

**Результат:** вы знаете свой стартовый уровень, запускаете учебную программу и можете объяснить, какие части в ней пока заменены заглушками. API-ключ и покупка подписки не нужны.

## Сначала определите точку входа

Этот маршрут готовит разработчика AI-приложений, а не исследователя, обучающего фундаментальную модель с нуля. Мы будем соединять обычный код, модель, данные и разрешённые действия. Это не отменяет необходимости понимать функции, типы, ошибки и тесты.

Ответьте действием, а не самооценкой: можете ли вы прочитать JSON из файла, написать функцию с проверкой входа, обработать ошибку, запустить тест и объяснить разницу двух версий в Git? Если нет — сначала пройдите нужные темы основ программирования. Существующие уроки общения с ИИ в этом репозитории **не заменяют** курс языка.

Выберите один основной язык. Встроенная лаборатория написана на Python и использует стандартную библиотеку. Опытный разработчик может перенести тот же контракт на TypeScript, C#, Java или Go. Одновременно изучать пять языков не требуется.

## Материалы в порядке изучения

1. Новичку в программировании: [CS50P](https://cs50.harvard.edu/python/) — Functions/Variables, Conditionals, Loops, Exceptions, Unit Tests, File I/O. Выполняйте задания курса по его правилам; наши упражнения — отдельная практика.
2. Разработчику, переходящему на Python: [официальный tutorial](https://docs.python.org/3/tutorial/) — разделы 4–8 и 12. Он предполагает базовое понимание программирования.
3. [Pro Git](https://git-scm.com/book/en/v2) — Getting Started, Git Basics и Basic Branching. Для старта достаточно clone, status, diff, add, commit и собственной ветки.

## Сделайте первый проход

1. Откройте [описание лаборатории](../lab/README.md). Скачайте именно ветку, указанную там: новые материалы могут ещё не находиться в `main`.
2. Проверьте `python --version` и `git --version`. Для учебного кода нужен Python 3.11+. Зафиксируйте реальную версию своей среды.
3. Из корня репозитория выполните `python -m unittest discover -s ai-in-code/lab -p 'test_*.py' -v`.
4. Запустите `python ai-in-code/lab/core.py`. Найдите в выводе пометку `mock`, результат расчёта и журнал шагов.
5. Прочитайте `Model`, `ScriptedModel`, `run` и `dispatch`. Проследите, как предложение модели становится вызовом обычной функции.
6. Измените числа учебного расчёта. Предскажите результат **до** запуска. Затем измените вход на неправильный тип и объясните отказ.

Это ваш первый артефакт: команда запуска, версия среды, один успешный случай, один отклонённый случай и объяснение пути данных. Сохраняйте его по [шаблону доказательства навыка](../WORKBOOK.md).

## Разберите пример

Учебный tool получает `{"unit_cents":250,"quantity":4}`. Ожидаемый результат — `1000` центов. Вызов модели может быть вероятностным, но умножение выполняется детерминированным кодом. Вход `{"unit_cents":250,"quantity":true}` должен быть отвергнут: логическое значение не является допустимым количеством, даже если язык допускает такое приведение.

В демонстрации ScriptedModel возвращает заранее заданные сообщения. Успешный запуск доказывает работу программы на этих сценариях, **не** качество LLM, не подключение OpenAI и не работу двух настоящих провайдеров.

## Проверьте понимание

Объясните без чата: кто вызывает модель; кто выполняет tool; где проверяется аргумент; что заменено mock; какие данные выходят в сеть. Для этого стартового примера правильный ответ на последний вопрос — никакие: сеть не используется.

**Готово:** вы повторили запуск, изменили условие, получили ожидаемый результат и можете показать отказ на плохом входе. Если тесты не запускаются, проверьте текущую папку, версию Python и имя файла, а не просите ИИ переписать весь проект.

**Самостоятельно:** добавьте тест на отрицательное количество. Объясните, почему просто удалить проверку ради зелёного теста — неправильное решение.
