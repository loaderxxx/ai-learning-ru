# 14. Выберите стек и углубление, не учите все framework сразу

[English](14-specialization.en.md) · [Карта пути](../README.md)

**До начала:** общий инженерный путь. **Результат:** одна выбранная специализация, реализованный перенос или расширение и объяснение компромиссов.

## Общие навыки важнее списка названий

Мы ищем способность построить проверяемую систему. Не нужно одновременно владеть Python, TypeScript, C#, Java, LangGraph, всеми SDK и несколькими базами. Выберите один основной стек и покажите переносимые принципы: контракты, инструменты, состояние, безопасность, evals и эксплуатация.

Сначала решите одну задачу средствами обычного SDK. Только затем добавляйте abstraction layer, если он уменьшает конкретную сложность. Ни framework, ни число агентов не являются самостоятельной мерой квалификации.

## Варианты

| Направление | Что изучить | Что показать |
|---|---|---|
| Python, управляемые процессы | [LangGraph](https://docs.langchain.com/oss/python/langgraph/overview), при необходимости [LiteLLM](https://docs.litellm.ai/docs/) | Workflow с явными состояниями и заменяемой моделью |
| Python, агентный runtime | [OpenAI Agents SDK](https://openai.github.io/openai-agents-python/) | Tools, ограничения, обработка результата и безопасная трассировка |
| TypeScript, AI-приложение | [AI SDK: text generation](https://ai-sdk.dev/docs/ai-sdk-core/generating-text), [tools](https://ai-sdk.dev/docs/ai-sdk-core/tools-and-tool-calling) | Backend с инструментами и корректным streaming/отменой |
| C# / .NET | [Microsoft Agent Framework](https://learn.microsoft.com/en-us/agent-framework/overview/) | Типизированные границы, инструменты, состояние и тесты |
| Поддержка существующего проекта C#/Python/Java | [Semantic Kernel](https://learn.microsoft.com/en-us/semantic-kernel/overview/) | Понимание текущего SDK и обоснованный план совместимости |
| Python, типизированные агенты | [Pydantic AI](https://pydantic.dev/docs/ai/overview/) | Проверка входов/выходов, dependency injection и контрактные тесты |
| Python, программируемые AI-функции | [DSPy](https://dspy.ai/) | Signature/module, метрика и сравнение до/после оптимизации |

Документация Microsoft на дату проверки описывает Agent Framework как преемника Semantic Kernel и AutoGen. Поэтому для нового .NET-проекта изучите актуальный путь, а для существующего не объявляйте миграцию выполненной без проверки кода. Не переносите перечень языков Semantic Kernel автоматически на другой framework.

DSPy особенно близок к идее «в обычной программе есть функция, которую выполняет AI»: вы описываете вход/выход и композицию модулей, затем можете оптимизировать программу по метрике. Это дополнительная специализация, а не замена тестов, прав доступа или изучения API.

## Одно упражнение на выбор

1. Возьмите фиксированную спецификацию Request Desk и сохранённый оценочный набор.
2. Выберите один новый инструмент из таблицы и сформулируйте, какую проблему он должен решить.
3. Прочитайте официальный quickstart и разделы по нужным операциям. Запишите версии SDK и модели.
4. Перенесите один компонент, не переписывая весь проект. Сохраните старый baseline.
5. Выполните те же тесты и evals. Сравните понятность, объём кода, воспроизводимость, задержку и расходы.
6. Запишите решение: принять, оставить для будущего или отказаться; укажите условия пересмотра.

## Что не обязательно для первого разговора

Multi-agent: сначала сравните одного исполнителя с двумя ролями на одинаковых задачах, включая стоимость координации. RAG и fine-tuning решают разные проблемы: дополнительный контекст не равен изменению весов. Fine-tuning, обучение собственных моделей, GPU-кластеры, Kubernetes и A2A — возможные дальнейшие направления, не обязательный пропуск в эту программу.

**Самостоятельно:** замените framework обычным кодом для одного сценария. Объясните, что потеряли и что упростилось.

**Готово:** вы владеете одним рабочим стеком, понимаете альтернативы и не выдаёте чтение tutorial за опыт эксплуатации.
