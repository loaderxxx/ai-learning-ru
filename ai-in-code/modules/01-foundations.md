# 01. Код, HTTP, JSON, асинхронность и тесты

[English](01-foundations.en.md) · [Карта пути](../README.md)

**До начала:** выполнен этап 00. **Результат:** маленькая программа с явными границами и тестами, которую можно расширить модельным адаптером.

## Что нужно понять

AI-приложение остаётся программой. Между запросом пользователя и результатом находятся ввод, валидация, сетевой клиент, логика, хранилище и интерфейс. Если перемешать всё в одной функции, замена провайдера или тестирование ошибки потребуют переписывать весь сценарий.

Начните с четырёх частей: `domain` описывает допустимые данные и правила; `model_adapter` переводит внутренний запрос во внешний API; `tools` выполняют разрешённые операции; `application` управляет последовательностью. Лаборатория компактна ради чтения; в своём проекте разделите эти роли, когда файл станет трудно проверять. Не создавайте десятки абстракций заранее.

JSON — формат обмена, не гарантия корректного значения. Строка `"4"`, число `4`, `null`, пустой список и отсутствующее поле имеют разные значения. Тип в аннотации Python или TypeScript сам по себе не проверяет недоверенный ответ, полученный по сети.

Асинхронность полезна, когда программа ждёт ввод-вывод. Она не отменяет timeout, ограничения параллелизма и отмену. Не запускайте сотни модельных запросов одновременно только потому, что доступен `gather`. Сначала ограничьте очередь и число активных операций.

## Читать и пробовать

1. [Python Tutorial](https://docs.python.org/3/tutorial/): Data Structures, Modules, Input and Output, Errors and Exceptions, Virtual Environments. Прочитайте один раздел — сразу реализуйте соответствующую часть упражнения.
2. [MDN: HTTP](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Overview): request/response, methods, headers, status codes. Нарисуйте один POST-запрос и ответ с ошибкой.
3. [asyncio: coroutines, cancellation, timeouts](https://docs.python.org/3/library/asyncio-task.html). Сначала изучите последовательный вызов, затем два независимых ожидания и их отмену.
4. Для альтернативного стека: [TypeScript Handbook](https://www.typescriptlang.org/docs/handbook/intro.html), особенно narrowing и обработка неизвестного входа.

## Практика по шагам

1. Создайте вход `Request` с `request_id`, `tenant_id`, `text`. Пока используйте только вымышленные данные.
2. Напишите `validate_request`: пустой текст, нестроковый ID и слишком длинный текст возвращают явную ошибку. Предельную длину выберите как условие своего учебного проекта и запишите.
3. Добавьте `calculate_total(unit_cents, quantity)`. Используйте целые денежные единицы минимального номинала, задайте пределы и запретите Boolean, отрицательные значения и лишние поля.
4. Создайте интерфейс модельного клиента. Для тестов он возвращает заданное сообщение или поднимает конкретную ошибку. Сеть пока не нужна.
5. Отделите конфигурацию от кода. В `.env.example` допустимы только названия переменных и безопасные пустые значения; реальный `.env` исключите из Git.
6. Напишите позитивные и негативные тесты. Отдельно проверьте сериализацию результата и сохранение `request_id`.
7. Сделайте небольшую правку в собственной ветке, прочитайте diff и сохраните понятный commit.

## Контрольный пример

Для `unit_cents=199`, `quantity=3` правильный результат — `597`. Для `quantity="3"` выберите и документируйте политику: строгий отказ либо явное преобразование **до** доменной функции. В этом курсе используем строгий отказ, чтобы не прятать ошибки интеграции.

Пустой ответ внешнего сервиса не превращается в успешный ответ с пустым текстом. Успех, неверный вход и технический сбой должны различаться так, чтобы вызывающий код мог принять решение без анализа человеческого сообщения об ошибке.

## Что показать

Покажите чистую установку/запуск, diff одного изменения, тест ошибки и место, где заменяется адаптер. Объясните разницу между исключением, HTTP-статусом и бизнес-статусом.

**Самостоятельно:** добавьте искусственную задержку и общий deadline. Докажите, что отменённая операция не продолжает незаметно изменять состояние. Не используйте настоящий платный API для этой проверки.

**Готово:** входы проверяются, обычные расчёты не делегированы LLM, сетевой клиент заменяем, ошибки воспроизводятся тестом.
