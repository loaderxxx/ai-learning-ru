# 03. Первый настоящий вызов модели и структурированный результат

[English](03-model-api.en.md) · [Карта пути](../README.md)

**До начала:** есть спецификация и mock. **Результат:** заменяемый модельный адаптер; живой запуск отмечается отдельно от офлайн-теста.

## Как проходит вызов

Внешняя модель — сетевой сервис. Программа собирает инструкции, вход и разрешённый контекст, передаёт их через SDK/HTTP, получает ответ и проверяет его. SDK — библиотека клиента, а не сама модель. Подписка на интерфейс чата не считается подтверждением доступного API: проверяйте доступ и бюджет своего аккаунта.

Внутренний результат приложения должен быть независим от SDK: статус, полезные данные, реальная идентификация модели, usage при наличии и техническая ошибка при сбое. Не выдавайте нулевую стоимость, если usage неизвестен. Храните статус `unknown` отдельно от измеренного нуля.

Три проверки идут последовательно: ответ завершён; структура соответствует контракту; содержание подтверждено исходными данными. Отказ модели, обрыв и превышение лимита — не успешный JSON. Structured output помогает с формой, но не доказывает истинность значений.

## Материалы

1. [OpenAI quickstart](https://developers.openai.com/api/docs/quickstart): ключ, установка SDK, первый Responses-вызов. Либо используйте официальный quickstart доступного провайдера.
2. [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs): схема, обязательные поля, поддерживаемое подмножество JSON Schema, отказ и неполный ответ.
3. [Claude tool-use overview](https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview) и [Gemini function calling](https://ai.google.dev/gemini-api/docs/function-calling): просмотрите различия форматов. Изучать все провайдеры сейчас не нужно.

## Пошаговый запуск

1. Создайте отдельное виртуальное окружение. Устанавливайте SDK из официального источника, проверьте версию и зафиксируйте зависимости. Не копируйте неподтверждённую команду установки из случайного чата.
2. Выберите модель, реально доступную в аккаунте. Её идентификатор храните в конфигурации; пример из статьи может уже не соответствовать вашему доступу.
3. Передайте ключ процессу через защищённое окружение. Не помещайте его в Git, frontend, скриншот, лог или команду, сохраняемую в shell history.
4. Отправьте один синтетический запрос, например классификацию: `"Please explain the club opening hours"`. Допустимые категории: `faq`, `calculation`, `draft`, `unknown`.
5. Получите объект с категорией и обоснованием, привязанным к входу. Проверьте типы и допустимые значения. Версия prompt и схемы должна попасть в запись эксперимента.
6. Внедрите адаптер в приложение. Для тестов оставьте ScriptedModel; интеграционные тесты запускайте отдельной явной командой.
7. Повторите на пяти заранее размеченных примерах и сохраните все результаты, включая ошибки.

Минимальный стартовый фрагмент для отдельного эксперимента — **не** полный адаптер, не вызов tools и не проверенная здесь живая интеграция:

```python
import os
from openai import OpenAI

client = OpenAI(timeout=20.0, max_retries=0)
response = client.responses.create(
    model=os.environ["OPENAI_MODEL"],
    input="Classify this synthetic request: explain the club opening hours.",
)
print(response.output_text)
```

После первого запуска замените свободный текст структурированным форматом по документации. `20` секунд — параметр примера, не универсальный SLA. Временные/токенные пределы выбирайте осмысленно для задачи.

## Негативные проверки

Без платных вызовов подмените транспорт: неверный ключ → конфигурационная ошибка без бесконечных повторов; timeout → технический статус; неизвестная категория → ошибка контракта; валидный JSON с неверной категорией → ошибка качества. Последнюю нельзя обнаружить одной JSON Schema.

Streaming добавляйте после обычного ответа. Фрагмент аргументов tool не исполняйте: сначала дождитесь завершённого сообщения, затем валидируйте. Частично показанный ответ должен быть помечен незавершённым при обрыве.

**Готово:** есть команда запуска, версия SDK, модель, пять результатов и отдельная отметка `LIVE VERIFIED` либо `NOT RUN`. Без доступа завершите контрактную часть и сохраните точный пробел; не называйте mock интеграцией.
