# 6. Законченный кейс вместо коллекции чатов

**Результат:** короткая работа, которую другой человек может проверить. Ориентир — 60–90 минут после любой из миссий. Публичное размещение необязательно.

Выберите один результат: карточку документов, отчёт по данным, сравнение подходов, базу знаний или схему автоматизации. Можно собрать все части вокруг одного сюжета, но для первого завершения достаточно одной. Кейс нужен, чтобы объяснить полученный навык, а не создать впечатление готовой промышленной системы.

## Соберите работу

Создайте папку или документ с четырьмя частями:

1. **Задача.** Для кого результат, какой вопрос решается, какие исходные данные разрешены.
2. **Результат.** Финальная таблица, записка, небольшой проект или протокол процесса.
3. **Проверка.** Исходники, расчёт или сценарии; отмеченные ошибки и фактические исправления.
4. **Границы.** Что осталось неизвестным, не запущено или требует другого инструмента.

Используйте [RESULT.md](../templates/RESULT.md). Ссылки на исходники должны открываться у проверяющего. Если даёте код, укажите одну рабочую команду и проверенную версию среды. Если используете чат, сохраните существенный запрос и результат, а не полную личную переписку.

## Пример честного описания

«На синтетической выгрузке из десяти строк выделены оплаченные заказы без конфликтов. Дубли и отсутствующие суммы отмечены отдельно, валюты не смешаны. Расчёт проверен вручную и локальной программой. Автоматический импорт из внешнего сервиса и бухгалтерская корректность реальных операций не проверялись».

Не превращайте эти слова в шаблон для любой работы: описание должно соответствовать вашему фактическому результату.

## Передайте на проверку

Попросите знакомого, который согласился участвовать, найти одно подтверждение, повторить один расчёт и задать один вопрос без ответа в данных. Если проверяющего нет, проведите повтор самостоятельно позже и назовите это самопроверкой. Не отмечайте независимую проверку по ответу того же чата, который готовил результат.

Проверка может выявить расхождение в требованиях. Например, один человек считает сумму известных оплат, другой ожидает движение средств с возвратами. Сначала уточните показатель, потом исправляйте результат.

## Перенесите навык

Измените одно условие и повторите работу:

- для документов — новая вместимость в версии 3;
- для данных — дополнительный оплаченный заказ в отдельной валюте;
- для исследования — другой обязательный критерий;
- для базы — удалённый источник;
- для автоматизации — повтор после прерванного запуска.

Сохраните, что пришлось изменить. Это сильнее, чем повторить готовый ответ на уже знакомом примере.

## Усложнение для разработчика

Сделайте небольшой воспроизводимый пакет с исходниками, README и проверкой одного нового граничного случая. Примените review из [продвинутого маршрута](../../advanced/modules/07-review.md). Если используете API, отдельно покажите реально выполненный вызов и обезличенный результат; наличие адаптера не считается интеграцией.

## Приёмка

Задача понятна без устного объяснения. Проверка воспроизводима. Указано, где использован ИИ и что проверил человек. Нет неподтверждённых обещаний экономии времени, дохода, сертификата или готовности к промышленному использованию. По переносу навыка видно хотя бы одно новое условие.
