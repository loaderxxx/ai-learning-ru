# 2. Данные без красивых ошибок

**Результат:** проверенный отчёт по десяти строкам. Ориентир — 60–90 минут. Основной путь выполняется в чате и на калькуляторе; Python нужен только для расширения.

## Сначала договоритесь, что считаете

Откройте [orders.json](../fixtures/orders.json) — это вымышленные записи заказов, не бухгалтерские данные. `row` обозначает строку выгрузки, `order_id` — заказ. Одинаковый заказ может появиться дважды. Сумма без валюты ничего не означает; отсутствие суммы не равно нулю.

Наш конкретный вопрос: **какова сумма известных оплаченных заказов без конфликтов, отдельно по каждой валюте?** Это не прибыль и не полный денежный поток. Возвраты исключаются из этого показателя, а не вычитаются как отрицательные операции. Для другого показателя потребуется другой договор.

## Правила этой задачи

- Учитываем только `paid` с известной суммой.
- Точное повторение одного заказа после нормализации суммы учитываем один раз.
- Если один `order_id` имеет разные сумму, валюту или статус, исключаем всю группу до уточнения.
- RUB и USD считаем отдельно; курс не придумываем.
- `1 500,00` означает 1500.00. Пустая сумма остаётся неизвестной.
- Для каждой неучтённой строки указываем причину.

Правило исключения всей конфликтной группы выбрано для упражнения. В реальной системе может существовать журнал статусов, но в нашем наборе его нет. Выбирать последнюю строку как «правильную» без такого основания нельзя.

## Выполните без кода

1. Попросите чат показать все десять строк таблицей без изменения значений.
2. Попросите применить правила и показать: включённые строки, исключённые строки с причинами, суммы по валютам.
3. Проверьте вручную одну нормализацию, дубль, конфликт, пропуск и обе итоговые суммы.
4. Попросите написать вывод максимум из трёх предложений и проверить, не называет ли он показатель прибылью.

```text
Проанализируй приложенный orders.json по правилам из задания.
До расчёта повтори определение показателя. Покажи все строки, попавшие
и не попавшие в него. Не заменяй null нулём и не объединяй валюты.
Если выполняешь код, покажи расчёт; если не выполняешь — прямо укажи это.
```

ChatGPT поддерживает анализ структурированных файлов и в некоторых задачах выполняет Python; доступность зависит от аккаунта. Важны просмотр метода и сверка, а не само сообщение «я посчитал». Официальная справка: P01 в [источниках](../SOURCES.md).

## Усложнение для разработчика

Запустите [готовую лабораторию](../lab/README.md), сравните её отчёт со своим. Затем добавьте новую строку с собственным ожидаемым результатом. Например, новый оплаченный заказ на 0.10 RUB должен увеличить рублёвый итог ровно на 0.10; строка с `NaN` должна привести к ошибке входа.

Для расчёта используйте десятичную арифметику или целые минимальные единицы. В образце применяется `Decimal` из строк; это не проверка финансовой модели и не универсальный импортёр любых банковских выгрузок. Формат и ограничения определены в README лаборатории.

## Приёмка

Каждая из десяти строк объяснена ровно один раз. Ни дубль, ни две конфликтные строки не увеличили итог. Две валюты не сложены. [Контрольный разбор](../fixtures/ANSWER_KEY.md) открывайте после собственной попытки.

Запишите не только число, но и определение показателя. Без него нельзя понять, правильно ли посчитан другой отчёт.
