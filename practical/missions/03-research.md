# 3. Исследование, которое помогает решить

**Результат:** одна страница сравнения двух способов организовать учебную базу документов. Ориентир — 60–90 минут. Пользоваться поиском можно самостоятельно или через ИИ; важные страницы откройте лично.

## Решение до поиска

Вымышленной группе нужно работать с пятью общедоступными текстами: отвечать на вопросы с источниками и заменять устаревшую версию документа. Участники используют телефон и компьютер. Выберите два подхода: обычный чат с приложенными источниками и специализированная тетрадь источников, например NotebookLM / Gemini Notebook. Если один недоступен, сравнивайте документацию и помечайте отсутствие практической проверки.

Запишите четыре обязательных критерия: источник ответа можно открыть; старую версию можно исключить; незнакомый вопрос не вызывает выдумку; участник может получить результат на своём устройстве. Цена и лимиты могут влиять на выбор, но фиксируйте их только с датой и ссылкой, без обещаний всем участникам одного доступа.

## Выполните исследование

1. Найдите официальную справку каждого подхода. Разделяйте описание продукта, рекламное обещание и свой тест.
2. Для каждого критерия заполните [таблицу сравнения](../templates/COMPARISON.md): утверждение, URL, дата, подтверждение, ограничение.
3. Проверьте, кому принадлежит страница и что говорят другие источники об авторе или утверждении. Приём выхода за пределы самого сайта описан в программе P08 — это полезный дополнительный взгляд, особенно для незнакомого поставщика.
4. Найдите аргумент против предварительно понравившегося варианта. Если его не нашли, зафиксируйте, где искали, а не выдумывайте слабость.
5. Проведите одинаковый маленький тест: один вопрос из версии 2, один вопрос без ответа и один вопрос после замены источника. Одинаковые данные важнее красивых демонстраций.
6. Напишите выбор: «Для этих условий выбираю…; потому что…; решение изменится, если…».

```text
Помоги сравнить два подхода по моим четырём критериям.
Отдели подтверждённое документацией от того, что нужно проверить в аккаунте.
Не заполняй неизвестные ячейки догадками. Найди условие, при котором
предварительно выбранный вариант окажется неудобен.
```

Если чат не имеет веб-поиска, дайте ему выдержки со ссылками и датами. Не просите оформить выдуманные URL. Количество ссылок само по себе не делает сравнение сильнее: пять пересказов одной рекламы не равны пяти независимым проверкам.

## Усложнение для разработчика

Сохраните сравнение в JSON: `criterion`, `claim`, `source_url`, `checked_at`, `evidence_type`, `test_status`. Значения `not_tested` и `unknown` допустимы. Проверяйте наличие полей программно; достоверность ссылок и соответствие содержанию проверяйте отдельно.

Добавьте локальный вариант как третий только при наличии реальной причины: например, задача не допускает загрузки документов в выбранный сервис. Не объявляйте локальное решение автоматически лучше по всем критериям — его обслуживание тоже входит в стоимость.

## Приёмка

Есть два сравнимых подхода, четыре критерия, минимум один открытый вопрос и один фактор, меняющий решение. По каждой фактической возможности видно, откуда она известна. Неисполненный тест обозначен как неисполненный. Проверяющий может понять выбор без чтения всего чата.

Стартовые источники: P01, P03–P04 и P08 в [каталоге](../SOURCES.md). Это упражнение в проверке, не рейтинг лучших сервисов.
