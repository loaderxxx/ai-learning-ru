# Change Gym: проверьте качество проверки

Синтетический реестр заданий для продвинутого маршрута. Python 3.11+, стандартная библиотека, без сети и внешних сервисов. Данные живут в памяти одного процесса.

## Запуск из корня репозитория

```bash
python3 advanced/labs/change-gym/run_checks.py
python3 advanced/labs/change-gym/compare_suites.py
```

Эталон должен пройти 17 контрактных тестов. Сравнение показывает: 2 smoke-теста пропускают все 6 подготовленных дефектных вариантов; контрактные тесты обнаруживают все 6.

## Один показательный дефект

```bash
python3 advanced/labs/change-gym/run_checks.py --variant partial_batch --suite smoke
python3 advanced/labs/change-gym/run_checks.py --variant partial_batch --suite contract
```

Первая команда должна завершиться с кодом 0; вторая — с кодом 1. Вторая команда обнаруживает намеренно внесённую ошибку. Исправлять инфраструктуру ради зелёного результата не нужно.

`compare_suites.py` возвращает ненулевой код, если контракт не прошёл эталон. Он не является универсальным CI-gate по mutation score. Если добавляете свои варианты, проверяйте их статус явно. В отчёте `failures` и `errors` могут считать неуспешные subtests, поэтому их число не обязано совпадать с числом методов тестов.

## Что упражнение доказывает

Оно показывает способность двух конкретных наборов обнаружить шесть известных ошибок. Мутации написаны вручную. Здесь не используется автоматический mutation engine и не измеряется качество Cursor/ChatGPT. Видимые примеры легко подогнать; для итоговой работы нужны новые случаи.

Реестр не является настоящей очередью задач. В нём нет долговечности, авторизации, межпроцессной атомарности, concurrency control или внешних эффектов. Копирование состояния обеспечивает указанное поведение только в последовательном учебном процессе. Перенос на базу данных требует новых механизмов и тестов.
