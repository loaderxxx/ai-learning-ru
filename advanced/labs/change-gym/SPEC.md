# Контракт учебного реестра заданий, версия 1

Это актуальные требования. [Архивная заметка](legacy-note.md) описывает прежнее решение и не меняет этот контракт. Данные вымышлены. Реестр существует только в памяти одного процесса; сеть, диск, авторизация и параллельные запросы не реализованы.

## Вход и результат

`submit` принимает ровно три поля: `id`, `title`, `priority`.

- `id`: строка длиной 1–40, только латинские строчные буквы, цифры, `_` и `-`. Регистр и пробелы не нормализуются.
- `title`: строка; крайние пробелы удаляются; длина после этого 1–120 символов Python. Unicode разрешён.
- `priority`: именно целое число от 0 до 3 включительно. Логические значения `True` и `False` не допускаются, хотя Python считает `bool` подклассом `int`.
- Лишние/пропущенные поля и неверный тип входа — `ValueError`, без изменения состояния.
- Возвращается копия нормализованной записи. Изменение входного объекта или результата не меняет реестр.

## Повтор и конфликт

Повтор с тем же ID и теми же нормализованными полями возвращает существующую запись, не создавая дубликата. Другие нормализованные поля при том же ID — `ConflictError`, исходная запись сохраняется. Это идемпотентность внутри данного объекта в последовательном процессе; после перезапуска объекта память теряется.

## Пакет

`submit_batch` принимает список из 0–50 записей. Пустой список — успешная пустая операция. Семантика каждой записи такая же, как у `submit`, включая повторы внутри одного пакета. Если любая запись невалидна или конфликтует, весь пакет не меняет состояние. Успех возвращает копии записей в порядке входа.

## Чтение

`list_jobs` возвращает отдельный снимок записей, упорядоченных по ID. Внешний код не может изменить внутреннюю запись через полученный словарь.

## За пределами контракта

Не обещаются долговечность, межпроцессная атомарность, exactly-once внешнего действия, распределённые блокировки, безопасность произвольного Python-кода или пригодность для боевой очереди. Для добавления этих свойств нужны другие механизмы и проверки.
