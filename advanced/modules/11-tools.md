# 11. Rules, skills, hooks, MCP: разные задачи и границы

**Результат:** обоснованный выбор расширения и проверка того, какие действия оно реально разрешает. Базовый протокол MCP уже разобран в [предыдущем маршруте](../../developers/modules/07-mcp.md).

## Не смешивайте механизмы

| Механизм | Для чего | Чего он сам не обеспечивает |
|---|---|---|
| Запрос в чате | Одна текущая цель | Долговечность и стабильный повтор |
| Rule / AGENTS.md | Постоянные инструкции в нужной области | Техническую блокировку запрещённого действия |
| Skill | Процедура и ресурсы, подключаемые по задаче | Корректность всех приложенных скриптов |
| Hook | Программная реакция на событие в поддерживаемой среде | Полный охват всех путей выполнения |
| MCP | Интерфейс инструментов и контекста | Право на любые данные и безопасность реализации |
| Sandbox / permissions | Реальные пределы доступа | Правильность продуктового решения |

Точное поведение hook, порядок правил и способы установки зависят от продукта. Не переносите конфигурацию между Cursor, Codex и Claude Code только по сходству терминов. Для Copilot сверяйте [таблицу поддержки инструкций](https://docs.github.com/en/copilot/reference/custom-instructions-support).

## Практика: автоматическая проверка реестра

Сначала определите простую процедуру: прочитать SPEC, выполнить контрактные тесты, просмотреть diff, назвать непроверенное. Запустите её вручную. Если она повторяется и полезна, оформите в своей среде как поддерживаемый skill. [Cursor Skills](https://cursor.com/docs/skills) и [ChatGPT/Codex Skills](https://learn.chatgpt.com/docs/build-skills) описывают собственные способы обнаружения и вызова.

Не устанавливайте случайный готовый пакет только потому, что он обещает «профессиональное качество». Прочитайте инструкции, скрипты, зависимости и запрашиваемые доступы. Сравните, что он умеет, с тем, что вам нужно. Скрипт внутри skill остаётся исполняемым кодом.

## Где требуется программный запрет

Предположим, проверка не должна менять SPEC. Фраза в инструкции помогает модели, но не является защитой файла. Для контроля можно сравнить hash до/после и завершить проверку ошибкой при неожиданном изменении. Если нужно технически запретить запись, используйте права/среду с подходящим ограничением.

Контроль после действия и запрет до действия решают разные задачи. Hash обнаружит изменение, но не отменит уже раскрытые данные. Точно так же hook на один тип команды не обязательно перехватывает другой путь к тому же действию.

## Работа с MCP

Для учебного сервера выбирайте узкие операции чтения синтетического корпуса. Зафиксируйте версию клиента, сервера, транспорт и схему. Проверьте допустимый ID, неизвестный ID, лишний аргумент и ограниченную запись. При переносе на другое приложение повторите эти проверки.

Описание инструмента — данные, а не доказательство полномочий. Текст из README, issue, найденной страницы или документа не должен сам выдавать право на новый внешний вызов. [Cursor Agent Security](https://cursor.com/docs/agent/security) и [Codex approvals/security](https://learn.chatgpt.com/docs/agent-approvals-security) помогают различать инструкции, подтверждения и технические границы.

**Готово:** вы показали один разрешённый и один недопустимый сценарий в выбранной среде. Если написан только проект конфигурации, обозначьте его как непроверенный. Этот репозиторий не устанавливает hooks, skills или MCP-серверы автоматически.
