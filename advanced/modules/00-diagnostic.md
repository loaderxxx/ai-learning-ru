# 00. Вы уже пользуетесь ИИ. Что проверим дальше?

**Результат:** первый запуск тренажёра и выбранный личный маршрут. Ориентир: 45–60 минут при установленном Python и знакомом Git. Это оценка нагрузки, не таймер экзамена.

## Входная задача

Агент написал изменение, тесты зелёные. Можно ли принимать? В нашей лаборатории шесть разных ошибочных реализаций проходят один и тот же слабый набор тестов. Ваша задача — понять, какого требования не хватает в проверке, а не заставить консоль показать ещё больше зелёных строк.

Если репозиторий уже есть, сначала сохраните свои изменения и обновите его обычным для вас способом. Для новой копии:

```bash
git clone https://github.com/loaderxxx/ai-learning-ru.git
cd ai-learning-ru
python3 advanced/labs/change-gym/run_checks.py
python3 advanced/labs/change-gym/compare_suites.py
```

Нужен Python 3.11+. В Windows команда может называться `py` или `python`. Сторонние пакеты, API-ключи и сеть для самого тренажёра не нужны. Не запускайте второй clone поверх своей существующей папки.

Ожидаемый результат: эталон проходит 17 проверок; слабый набор не обнаруживает ни одного из шести дефектных вариантов; контрактный обнаруживает все шесть. Это результат на шести заранее подготовленных ошибках, а не гарантия отсутствия других ошибок.

## Посмотрите на конкретное расхождение

```bash
python3 advanced/labs/change-gym/run_checks.py --variant partial_batch --suite smoke
python3 advanced/labs/change-gym/run_checks.py --variant partial_batch --suite contract
```

Первая команда успешна. Вторая должна завершиться с ошибкой тестов и кодом 1: часть пакета записалась до отклонения неправильной записи. Не исправляйте тест так, чтобы он принял это поведение. Прочитайте [SPEC.md](../labs/change-gym/SPEC.md): пакет обязан применяться целиком либо не менять состояние.

Теперь попросите доступный вам ИИ объяснить причину, передав действующую спецификацию, соответствующий тест и реализацию. Проверьте объяснение по коду. Если используете обычный чат, приложите файлы: ссылка на папку в вашем компьютере не даёт ему доступа.

## Диагностика навыков

| Вопрос | Нужное доказательство | Если пока сложно |
|---|---|---|
| Какой документ актуален? | Отличаете SPEC от архивной заметки | Модули 01–03 |
| Какие изменения допустимы? | Формулируете контракт до генерации | 04 |
| Почему появился дефект? | Минимальный сценарий и наблюдение | 05 |
| Почему тесты его пропустили? | Находите отсутствующее утверждение | 06–07 |
| Как не сломать старого клиента? | Проверка совместимости | 08 |
| Как продолжить завтра? | Сохранённое состояние и проверенный следующий шаг | 09 |
| Как разделить работу? | Разные ветки и проверка после объединения | 10 |
| Что агент вправе выполнить? | Различаете инструкцию и техническое разрешение | 11–12 |
| Как подтвердить готовность интерфейса? | Проверяете сценарий, а не только скриншот | 13 |
| Помог ли ИИ экономически? | Считаете время до принятого изменения | 14 |

Знакомые темы пропускайте через доказательство: команда, результат, объяснение. Не оценивайте себя по числу используемых моделей или установленных расширений.

## Первая запись

Заполните [паспорт запуска](../templates/RUN.md): среда, версия репозитория, задача, команды, результат, что вы ещё не проверили. Добавьте одну фразу: «Слабый тест не обнаружил ___, потому что ___». Это полезнее длинного пересказа ответа модели.

**Готово:** вы воспроизвели успешный и неуспешный запуск, нашли нарушенное требование и выбрали следующий модуль. Без ИИ можно выполнить весь локальный эксперимент; эффективность работы с конкретным агентом в таком случае не измерена.
