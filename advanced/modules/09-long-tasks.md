# 09. Длинная задача: сделайте продолжение воспроизводимым

**Результат:** новый сеанс может продолжить работу, не восстанавливая намерения по всей переписке.

## Что теряется между сеансами

Файлы, история разговора, рабочее дерево, процессы и доступ к внешним сервисам — разные состояния. Сохранённый чат не гарантирует живой процесс. Commit не сохраняет незакоммиченные файлы. Краткое резюме не содержит автоматически все условия спецификации.

Для учебного продолжения сохраните: цель, текущую версию, выполненные изменения, последние фактические проверки, оставшийся вопрос и ближайший шаг. Ссылка на тестовый отчёт полезнее заявления «почти всё готово». Используйте [HANDOFF.md](../templates/HANDOFF.md).

## Разбейте задачу на проверяемые участки

Для фильтра и экспорта реестра выберите три результата: фильтр соответствует контракту; экспорт имеет определённую форму; новая сессия воспроизводит оба. Два первых участка можно проверить отдельно. Выпуск требует общего запуска после их соединения.

В каждом участке определите условие остановки: что считается достаточным, когда требуется новая информация, при какой ошибке надо пересмотреть план. «Работай, пока не будет идеально» не ограничивает ни объём, ни время.

## Эксперимент с прерыванием

1. Выполните первую часть и запишите текущий commit либо явно опишите незакоммиченный diff.
2. Сохраните команду проверки и её результат.
3. Закройте рабочую беседу после завершения операции, не во время записи данных.
4. Откройте новую и передайте только handoff с доступом к учебной копии.
5. Попросите сначала сверить документ с фактическими файлами, затем продолжить.

Успех — не красивый пересказ. Продолжение должно заметить, если код изменился после handoff, и выполнить оставшуюся часть без повторной реализации готового.

## Контекст и компрессия

Короткое резюме сохраняет важные решения, но может потерять отрицательные условия: «не менять конфликт», «не добавлять сетевой вызов», «проверен только Python одной версии». Поэтому долговечные требования живут в файлах, а резюме указывает на них. Не включайте подробности каждого поиска, если они не меняют следующее действие.

В [эксперименте OpenAI с длинной задачей](https://developers.openai.com/blog/run-long-horizon-tasks-with-codex) показана роль внешнего состояния и обратной связи. Это инженерный пример автора, не гарантия, что любая задача будет надёжно выполнена без наблюдения. Время работы и число строк кода не являются критериями качества вашего результата.

## Checkpoint, Git и внешний мир

У конкретного продукта checkpoint может покрывать только часть изменений. Например, [Claude Code](https://code.claude.com/docs/en/best-practices) отдельно описывает границу файловых изменений, сделанных его инструментами. Проверяйте поведение выбранного продукта, а не переносите ожидания по одинаковому слову.

Откат кода не отменяет отправленное письмо, запись во внешней базе или публикацию. В этой лаборатории внешних действий нет. Если ваш проект их добавляет, план восстановления должен учитывать каждое действие отдельно.

**Готово:** вы действительно продолжили работу в новом сеансе, сверили состояние и сохранили фактический итог. Если выполняли только написание handoff, отметьте «документ подготовлен; продолжение не проверено».
