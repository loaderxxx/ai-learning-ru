# 14. Измеряйте время до принятого результата

**Результат:** небольшой собственный эксперимент, показывающий цену конкретного рабочего процесса. Без обещаний универсального ускорения.

## Что входит во время

Считайте постановку задачи, подготовку контекста, ожидание, чтение diff, исправления, проверки и объединение. Если модель написала код за минуту, а вы час устраняли ошибки, минуту нельзя выдавать за стоимость изменения. Отдельно полезно измерять ваше активное время и календарное время до готового результата.

Заполните [EXPERIMENT.md](../templates/EXPERIMENT.md). Для каждого запуска сохраняйте одинаковое определение готовности, исходную версию, выбранный инструмент/модель и фактические результаты. Если название модели или режим недоступны, не угадывайте их по скорости ответа.

## Сравнение двух способов

Выберите несколько небольших задач похожего масштаба: фильтр, сортировка с новым условием, экспорт, новый отрицательный тест. Распределите их между способами работы и меняйте порядок. Повторное решение ровно той же задачи обычно легче из-за запоминания; это мешает честному сравнению.

| Показатель | Как записать | Ограничение |
|---|---|---|
| Время до приёмки | От начала постановки до общего прохода проверок | Зависит от опыта и сложности |
| Активное время человека | Подготовка, review, исправления | Самозамер приблизителен |
| Дефекты | Подтверждённые случаи по одинаковому набору | Набор не покрывает всё |
| Расход сервиса | По доступному учёту аккаунта | Подписка и API считаются по-разному |
| Повторная работа | Переделки после review | Не всегда видна сразу |

Несколько задач дают наблюдение о ваших условиях. Они не доказывают причинный эффект для всех разработчиков. Если одна задача оказалась существенно сложнее, объясните это, а не скрывайте выброс.

## Выбор модели и режима

Начинайте с доступного вам режима и проверяемой задачи. Усложняйте рассуждение или меняйте инструмент, если наблюдение показывает конкретный предел: не найдена связь между модулями, неверно разобран конфликт, нарушен контракт. Не назначайте самый дорогой режим каждой операции по умолчанию.

Сравнивайте результаты на одном требовании. Более подробный ответ может быть полезнее для исследования, но мешать простой правке. Чем сильнее различаются инструменты выполнения и предоставленный контекст, тем меньше оснований приписывать разницу только модели.

## Бюджет длительного запуска

До запуска задайте предел календарного времени, этап после которого нужен просмотр, критерий остановки при повторяющейся ошибке и допустимые внешние расходы. Проверяйте, являются ли продуктовые лимиты технически жёсткими или лишь уведомлением. Текст «не трать больше» сам по себе не создаёт учёт и блокировку.

Фиксированных тарифов здесь нет: они меняются и зависят от плана. Перед расходом откройте актуальные условия именно выбранного сервиса. Для локальной лаборатории расходы на API равны нулю, поскольку вызовов модели в ней нет; использование вашего AI-редактора учитывается отдельно.

**Готово:** есть хотя бы два сопоставимых наблюдения, разбор качества и ограничений. Решение звучит конкретно: «для этой задачи этот способ оказался удобнее при таких условиях». Для расширения наблюдаемости см. [Hugging Face Agent Observability](https://huggingface.co/learn/agents-course/bonus-unit2/introduction).
