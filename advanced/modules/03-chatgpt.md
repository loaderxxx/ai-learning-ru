# 03. ChatGPT: от обсуждения к проверяемому инженерному решению

**Результат:** короткая записка по выбору реализации и передача в Cursor без потери версии, требований и неизвестных.

## Сначала выясните, к чему есть доступ

ChatGPT, Codex и конкретная подключённая среда не взаимозаменяемы. В обычном обсуждении можно анализировать приложенные файлы. В среде с доступом к рабочей папке агент может читать и изменять её. Наличие инструмента или кнопки в другом аккаунте не означает наличие у вас.

[Projects and chats](https://learn.chatgpt.com/docs/projects) описывает совместное хранение чатов, файлов и инструкций. Сам ChatGPT Project не даёт прямой доступ к папке компьютера. Приложенный файл — снимок: после изменения кода надо проверить, какую версию читает собеседник. В IDE/CLI источником кода служит выбранный workspace, а не автоматически все файлы из веб-проекта.

## Задача для исследования

Предположим, учебный реестр должен переживать перезапуск. Рассмотрите два варианта: JSON-файл и SQLite. Цель — выбрать один для однопользовательского локального прототипа. Ограничьте исследование: не нужны Kubernetes, распределённая очередь и обзор всех баз данных.

Передайте модели действующий SPEC, текущую реализацию и условия: один процесс сейчас, возможное расширение позже, ошибочный пакет не должен оставлять частичную запись. Попросите таблицу: требование → механизм → источник → эксперимент, который подтвердит механизм в вашем проекте.

Пример запроса:

```text
Сравни два способа сохранять этот учебный реестр между запусками.
Не считай текущую атомарность в памяти доказательством надёжности на диске.
Для каждого варианта покажи поведение при ошибке записи и повторном ID.
Укажи официальные источники и отдели документированный факт
от своего проектного предложения. Закончи одним минимальным экспериментом.
Код пока не меняй.
```

## Проверка источника — отдельное действие

Откройте ссылку и найдите утверждение, на котором держится решение. Документ о транзакции не доказывает, что ваш код корректно её использовал. Статья об успешном агенте не доказывает такую же надёжность для вашей задачи. Если версия библиотеки отличается, сверьте API именно установленной версии.

[Web search](https://learn.chatgpt.com/docs/web-search) и deep research помогают находить и сопоставлять сведения. Доступ и расположение функций зависят от аккаунта и среды. Если функция недоступна, выполняйте тот же ограниченный обзор через официальные страницы вручную. Название режима не является оценкой достоверности отчёта.

## Передача в Cursor

Из длинного обсуждения оставьте [записку о решении](../templates/DECISION.md): выбранный вариант, отвергнутая альтернатива, основания, открытый вопрос, критерий экспериментальной проверки. Добавьте commit или точный снимок файлов. Cursor сначала сверяет это с текущим кодом, затем выполняет согласованную правку.

Обратная передача содержит diff, команды и фактические результаты. Не просите ChatGPT «подтвердить, что всё хорошо» по одному описанию успеха. Дайте проверяющему требование и наблюдение; его задача — найти неподтверждённый переход в рассуждении.

## Когда обсуждение заканчивается

Если различие вариантов уже выражено проверяемой гипотезой, следующий шаг — небольшой эксперимент. Ещё один большой обзор часто не добавляет основания. Если нужна информация, которой нет в доступных файлах, запишите её как неизвестную, а не заполняйте правдоподобным предположением.

**Готово:** другой человек понимает выбор, видит его ограничение и может повторить эксперимент. Решение хранится рядом с проектом; его актуальность не зависит от памяти одного длинного чата.
