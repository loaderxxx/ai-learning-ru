# 4. Оцениваем модель на новых заметках

**Цель:** понять, на каких случаях модель помогает, а где требует исправлений. Ориентир — 2–3 часа. Восемь примеров — учебная диагностика, не универсальный рейтинг моделей.

Откройте [набор случаев](../fixtures/review-cases.json). Каждый содержит вход и ожидание для проверяющего. **Модели передавайте только `input`**, иначе она увидит ответ. Если вы уже прочитали все ожидания и подстраивали систему под них, не называйте этот набор независимым тестом.

## Подготовка

Используйте C01–C04 для настройки запроса. После этого зафиксируйте модель, версию/тег, контекст, настройки и код. C05–C08 оставьте на первый отложенный прогон. После просмотра ошибок отложенного набора его повторное использование становится проверкой исправления; для нового независимого результата нужны новые случаи.

Для каждого случая запишите:

| Показатель | Как проверить |
|---|---|
| Форма | Шесть полей, строки или null, цитаты присутствуют |
| Смысл | Поправка учтена; неизвестное не придумано |
| Опора | Цитата действительно доказывает указанное значение |
| Результат | Принят без правки / исправлен / отклонён |
| Затраты | Ожидание модели и активные минуты человека отдельно |

Сбой формата и таймаут тоже входят в результаты. Не удаляйте неудачные попытки из отчёта. Если вы повторяли запрос, посчитайте все попытки и время исправлений.

## Проведите сравнение

Сначала получите карточки вручную по исходникам. Затем выполните один модельный прогон по фиксированным условиям. На маленьком наборе полезнее показать конкретные ошибки, чем одно число «точность 95%». Например: модель выбрала старое число участников или вычислила дату пятницы без основания.

Первый запуск может включать загрузку модели в память. Отдельно пометьте холодный и последующие запуски. Если наблюдаете потребление памяти, укажите средство измерения и фоновые приложения; не сравнивайте неописанные показатели из разных систем.

## Новое условие

Составьте ещё два синтетических примера с другими числами и порядком фраз, не меняя зафиксированную конфигурацию. Передайте их проверяющему вместе с собственным ключом. Если независимого проверяющего нет, отметьте самопроверку.

В [результате](../templates/RESULT.md) напишите конкретное решение: оставить конфигурацию для коротких заметок, попробовать другую модель или использовать ручной путь. «Локальная» описывает способ выполнения, а не гарантированное качество. Не публикуйте сравнение облачной и локальной модели как равное, если у них были разные входы, подсказки или доступ к источникам.
