# Ищем AI / LLM инженеров

**Ищем людей, которые умеют не просто пользоваться ChatGPT, а встраивать AI прямо в работающие программы, сервисы и бизнес-процессы.**

Нам интересны инженеры, которые могут соединить обычный код, несколько AI-моделей, API, инструменты и данные в одну управляемую систему.

Если вы уже умеете это делать — хотим познакомиться.  
Если пока умеете не всё — ниже есть конкретный маршрут, что изучить.

---

## Кого мы ищем

Нужен инженер, который понимает обычную разработку и умеет использовать LLM как **компонент программной системы**, а не как отдельный чат.

Подходящий кандидат способен собрать примерно такую схему:

```text
пользователь / сервис / событие
            ↓
      обычная программа
            ↓
        route_task()
      ┌─────┼─────────┐
      ↓     ↓         ↓
   модель A модель B  обычный код
      ↓     ↓         ↓
      tools / API / данные
            ↓
      проверка результата
            ↓
     следующий шаг системы
```

---

## Что нужно уметь

### 1. Нормально программировать

Нужна уверенная работа хотя бы с одним современным стеком:

- Python;
- JavaScript / TypeScript;
- C# / .NET;
- Java;
- Go или другим серверным языком — если можете показать эквивалентную реализацию.

Важно не название языка, а способность писать понятный код, работать с API, данными, ошибками, тестами и Git.

### 2. Вызывать AI-модели из кода

Нужно понимать:

- LLM API;
- SDK провайдеров;
- structured output;
- streaming;
- timeout / retry;
- rate limits;
- обработку ошибок;
- стоимость вызовов;
- безопасное хранение API-ключей.

### 3. Работать с несколькими моделями

Нужно уметь отделять бизнес-логику от конкретного провайдера.

Полезные навыки:

- единый интерфейс к разным моделям;
- routing;
- fallback;
- выбор модели под тип задачи;
- сравнение качества / скорости / стоимости.

Один из инструментов, который стоит знать: **LiteLLM**.

### 4. Tool / function calling

Нужно понимать, как дать модели доступ к ограниченному набору функций:

- получить данные;
- выполнить расчёт;
- обратиться к API;
- найти запись;
- изменить разрешённое состояние;
- передать задачу следующему компоненту.

Критично понимать границу:

**модель предлагает вызов → программа проверяет → программа выполняет.**

Нельзя просто доверять модели выполнение произвольных действий.

### 5. Orchestration и agent workflows

Нужно уметь связывать несколько шагов в контролируемый процесс:

- prompt/model → tool → проверка → следующий шаг;
- состояние workflow;
- branching / routing;
- циклы с ограничениями;
- retry и fallback;
- human approval там, где он нужен;
- несколько специализированных ролей только там, где это оправдано.

Полезный стек для изучения:

- **LangChain**;
- **LangGraph**;
- **OpenAI Agents SDK**;
- **Microsoft Semantic Kernel**;
- другие эквивалентные agent/workflow frameworks.

### 6. MCP и внешние инструменты

Плюсом будет понимание:

- MCP;
- подключения внешних tools;
- разрешений;
- read-only / write access;
- безопасных границ между моделью и внешней системой.

### 7. RAG и работа с данными

Желательно уметь:

- получать контекст из документов и баз данных;
- делать retrieval;
- работать с embeddings / vector search;
- возвращать источники;
- отличать найденный факт от генерации модели;
- строить проверки качества.

### 8. Evals, тесты и наблюдаемость

Нужен инженерный подход, а не «вроде отвечает нормально».

Важно уметь:

- делать набор тестовых случаев;
- измерять качество;
- ловить регрессии;
- логировать вызовы;
- видеть, какую модель и tool вызвала система;
- отслеживать ошибки и стоимость;
- воспроизводить проблемный сценарий.

---

## Что желательно показать

Не нужен огромный коммерческий проект. Нам важнее увидеть, что вы понимаете архитектуру.

Хороший демонстрационный проект:

1. принимает задачу;
2. выбирает одну из двух моделей;
3. вызывает модель через общий интерфейс;
4. при необходимости вызывает local tool или API;
5. проверяет аргументы;
6. обрабатывает ошибку / timeout;
7. умеет fallback;
8. логирует ход выполнения;
9. имеет несколько тестовых сценариев;
10. не хранит секреты в репозитории.

Если такой проект можно запустить и объяснить — это уже хороший разговор.

## Что мы НЕ ищем

Самого по себе умения:

- писать промпты;
- пользоваться ChatGPT;
- генерировать код в Cursor;
- копировать готового агента из tutorial;

недостаточно.

Нам нужен человек, который понимает, **что происходит между пользователем, кодом, моделью, инструментом, данными и результатом**, и способен сделать эту систему управляемой и проверяемой.

## Минимальная самопроверка перед разговором

Вы готовы к техническому разговору, если можете без подсказки объяснить:

- чем LLM API отличается от обычного чата;
- зачем нужен abstraction layer между кодом и моделью;
- чем tool calling отличается от обычного API-вызова;
- кто на самом деле выполняет tool;
- как подключить две разные модели к одному алгоритму;
- как сделать fallback;
- зачем нужны evals;
- почему agent нельзя давать неограниченные permissions;
- где лучше использовать обычный детерминированный код вместо AI.

И можете показать работающий код хотя бы на небольшой задаче.
