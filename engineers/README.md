# Ищем AI / LLM инженеров

## Не просто пользуйся AI. Создавай системы, в которых он работает.

**Ищем разработчиков, которые умеют соединять обычный код, модели, инструменты и данные в управляемый продукт. Уже умеете — покажите работу. Пока не всё умеете — пройдите конкретный учебный путь и приходите с результатом.**

[English invitation](README.en.md) · [Полный путь обучения](../ai-in-code/README.md) · [Главная репозитория](../README.md)

Нам интересен инженер, который может объяснить весь путь: запрос → программная логика → выбранная модель → разрешённая функция/API → проверка → результат. Умение писать промпты или генерировать код в редакторе полезно, но не заменяет понимание системы.

## Обязательная основа и желательные расширения

Не нужно знать все перечисленные языки и framework. Нужен один уверенный стек и доказательства навыков. Python или TypeScript удобны для прохождения примеров; C#/.NET, Java, Go и эквивалентная реализация тоже подходят.

## Что показать вместо длинного резюме

Небольшой собственный проект: принимает задачу, собирает контекст, выбирает обработчик по измеренному качеству и ограничениям, вызывает модель через адаптер, безопасно выполняет один tool, проверяет ответ, обрабатывает сбой и оставляет понятный журнал. Есть команда запуска, негативные тесты и объяснение, почему выбранная модель подходит задаче, а не просто дешевле остальных.

Не требуется коммерческий проект большого масштаба. Можно показать эквивалентную существующую работу или [учебный Request Desk](../ai-in-code/modules/15-capstone.md). Используйте синтетические данные, не публикуйте чужой закрытый код. Работа с mock допустима как учебный результат, но живые интеграции и их отсутствие обозначайте честно.

## Как откликнуться

Ответьте человеку, который прислал эту ссылку. Для публичного технического контакта можно [открыть GitHub Issue](https://github.com/loaderxxx/ai-learning-ru/issues/new) с темой `AI engineer — introduction`.

Достаточно коротко написать: основной стек; что уже строили с AI; ссылка на разрешённый к публикации пример или предложение приватной демонстрации; что сделали самостоятельно; какие навыки ещё изучаете. Телефоны, документы, адреса, API-ключи и конфиденциальные данные в публичный Issue не отправляйте.

Дальше предмет разговора — код, архитектура, ошибки и подход к работе. Коммерческие условия, занятость, география и конкретная роль обсуждаются отдельно; они пока не объявлены. Визуальные материалы с городом не являются обещанием офиса или релокации.

**Учись. Собери работающий пример. Покажи, как он устроен. Давай знакомиться.**
