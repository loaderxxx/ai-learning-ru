# Лаборатория: помощник по учебной базе знаний

Рабочая исходная версия для [маршрута разработчика](../../README.md). Все записи вымышлены. Код использует только стандартную библиотеку Python 3.11+.

**Режим:** локальный поиск и точное извлечение фрагмента. Здесь нет вызовов LLM, MCP-сервера, A2A, сетевых запросов и оплачиваемых сервисов. Эти интеграции добавляются участником в следующих модулях.

## Запуск из корня репозитория

```bash
python3 developers/labs/knowledge-assistant/assistant.py "python версия"
python3 -m unittest discover -s developers/labs/knowledge-assistant -p 'test_*.py' -v
python3 developers/labs/knowledge-assistant/evaluate.py
```

В Windows используйте доступную команду `py` или `python` вместо `python3`. Для выполнения нужен распакованный/клонированный репозиторий, а не только открытая страница GitHub.

Первый вызов должен вернуть статус `answered`, source ID `setup` и исходный текст о Python. Неверный/пустой запрос даёт объяснимую CLI-ошибку.

## Как устроено

Поиск нормализует регистр, выделяет слова и отбрасывает небольшой список служебных слов. Затем рассматривает только активные публичные документы и считает долю слов запроса, которые есть в тексте, заголовке или тегах. Совпадение не меньше 0,5 позволяет включить кандидата. Это наивная учебная эвристика, не вероятность правильности.

Ответ берёт текст первого кандидата целиком. Если кандидата нет — возвращает `not_found`. Схема проверяет типы; дополнительный `validate_answer` проверяет небольшое число правил, включая допустимые ID. Ни одна из этих проверок сама по себе не устанавливает, что текст ответил на смысл вопроса.

## Известные ограничения — ваши первые задачи

Синоним «кодовая инспекция» не связан с «ревью». Запрос «встреча адрес» может вернуть документ про встречу, в котором адреса нет. Эти случаи оставлены в наборе с ожидаемым правильным поведением. Исправление одного порога может улучшить отказ и одновременно ухудшить поиск.

`evaluate.py` формирует отчёт и завершается с кодом 0 даже при несовпадениях. Это команда измерения, не gate качества. Для собственной версии отдельно задайте, какие случаи обязаны проходить. Unit tests должны завершаться успешно, потому что проверяют контракт и ограничения кода, а не отсутствие всех смысловых ошибок.

Служебный маркер в JSON намеренно публично виден читателю репозитория: это синтетические данные для проверки логики приложения. Реальных секретов здесь нет. Политика `public`/`active` не заменяет аутентификацию, разграничение ролей или проверку доступа в реальном многопользовательском сервисе.

## Безопасный порядок расширений

1. Зафиксировать baseline и прочитать одну ошибку.
2. Улучшить поиск, проверить перенос на новые вопросы.
3. Добавить модель за отдельным интерфейсом, не расширяя права.
4. Проверить формат и смысл ответа раздельно.
5. Добавить MCP к уже проверенным функциям.
6. При обоснованной задаче попробовать A2A.

Тест с вредной строкой подтверждает только, что этот офлайн-код не исполняет текст. Он не является результатом проверки prompt injection против реальной модели.
