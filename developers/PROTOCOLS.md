# Карта протоколов и форматов

Названия часто встречаются рядом, но решают разные задачи. Сначала определите задачу интеграции, затем выбирайте инструмент. Проверка источников: 23.09.2026.

| Название | Задача | Пример в проекте | Что проверять отдельно |
|---|---|---|---|
| JSON | Передача структурированных данных | Объект ответа | Типы, допустимые значения и смысл |
| [JSON Schema](https://json-schema.org/understanding-json-schema/reference/object) | Описание формы объекта | Обязательные поля ответа | Поддерживаемый dialect/subset; истинность значений |
| HTTP | Обмен запросами и ответами | Endpoint приложения | Timeout, коды ошибок, авторизация, повтор |
| [OpenAPI](https://spec.openapis.org/oas/latest.html) | Описание HTTP API | Контракт `POST /answer` | Соответствие реальной реализации описанию |
| JSON-RPC | Вызов именованного метода | Сообщение протокола | ID, ошибки, правила конкретного binding |
| SSE | Поток событий от сервера | Постепенная доставка результата | Обрыв, завершение, возобновление; это не очередь |
| OAuth | Делегированный доступ | Токен доступа к удалённому ресурсу | Audience, срок, scope и серверная политика |
| [MCP](https://modelcontextprotocol.io/specification/2026-07-28) | Инструменты и контекст для AI-приложений | Поиск по учебному корпусу | Версия, транспорт, SDK, права и реальные side effects |
| [A2A](https://a2a-protocol.org/latest/specification/) | Взаимодействие отдельно предоставленных агентов | Асинхронное review | Владение задачей, артефакты, отмена, совместимость |
| Function calling | Предложение вызова функции моделью | `get_doc(id)` | Приложение валидирует и выполняет; формат зависит от API |
| CI/CD | Проверка и доставка изменений | Тесты, сборка, выпуск | Это процесс разработки, а не сетевой протокол |

## Как зафиксировать совместимость

В [паспорте](templates/INTEGRATION.md) запишите версию протокола, SDK, клиента, transport и результат обмена. Прочитанная редакция документации не гарантирует, что ваш клиент её поддерживает. У MCP редакция 2026-07-28 отличается от прежних примеров с session/initialize; подробности есть в [transport specification](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports).

## Три частые ошибки

**«Всё отвечает JSON, значит совместимо».** JSON описывает сериализацию, а не смысл сообщений. Два сервиса могут по-разному трактовать одинаковые поля.

**«Токен принят, значит действие разрешено».** Аутентификация и полномочия конкретной операции должны проверяться сервером. Scope и доступ к документу не назначает текст запроса модели.

**«Клиент получил timeout, можно повторить запись».** Сервер мог уже выполнить операцию. Идемпотентность проектируют на уровне действия и хранения результата.
