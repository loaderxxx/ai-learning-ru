# 00. Вход: что вы уже умеете и что попробуете сегодня

**Результат:** запущенный стенд, первая оценка его ошибок и выбранный маршрут. Ориентир — 45–90 минут при готовой среде. На этом шаге оплачивать API не требуется.

## Два разных применения ИИ

Когда вы просите Cursor объяснить функцию или модель предложить тест, ИИ помогает вам создавать программу. Когда ваша программа сама отправляет запрос модели и использует ответ, ИИ становится частью продукта. Это разные задачи. В первом случае вы проверяете внесённую правку. Во втором — дополнительно проектируете ошибки модели, задержку, расходы и поведение для пользователя.

Наш проект начинается с обычного кода: он ищет записи в синтетической базе и возвращает найденный фрагмент. Затем вы сможете заменить извлечение текста генерацией и сравнить результат. Так будет видно, какую пользу добавила модель и какие проблемы появились вместе с ней.

## Самодиагностика без экзамена

Попробуйте ответить действиями, а не «да, слышал термин».

| Проверка | Достаточный результат | Если пока не получается |
|---|---|---|
| Прочитать функцию | Объясняете её вход, выход и один случай ошибки | Возьмите знакомый язык и маленькую функцию |
| Запустить программу | Повторяете команду и понимаете код завершения | Проверьте установку и рабочую папку |
| Прочитать diff | Видите, какие строки изменились и зачем | Сначала выполните маленькую ручную правку |
| Написать проверку | Один пример проходит, другой ловит ошибку | Начните с `assert` или стандартного тестового инструмента |
| Прочитать JSON | Отличаете объект, список, строку и число | Посмотрите `documents.json` в стенде |
| Объяснить HTTP/API | Различаете запрос, ответ и ошибку | Можно пройти локальную часть, API изучить в модуле 03 |

Незнание Python не означает, что вы не программист. Стенд небольшой: можно изучить его или перенести на свой язык. Если незнакомы почти все пункты, сначала пройдите базовый курс программирования; [знакомство с ИИ](../../START_HERE.md) само по себе не заменит эту базу.

## Первый запуск

Откройте терминал в папке, где хотите хранить учебный проект. Команды ниже клонируют публичный репозиторий. Если уже скачали его, повторять `git clone` не нужно.

```bash
git clone https://github.com/loaderxxx/ai-learning-ru.git
cd ai-learning-ru
python3 --version
python3 developers/labs/knowledge-assistant/assistant.py "python версия"
python3 -m unittest discover -s developers/labs/knowledge-assistant -p 'test_*.py' -v
python3 developers/labs/knowledge-assistant/evaluate.py
```

Нужен Python 3.11 или новее. В Windows команда может называться `py` или `python`; используйте одно название во всех командах. Если Git недоступен, на странице репозитория можно скачать ZIP через меню Code, распаковать и открыть терминал в полученной папке.

Ожидайте ответ со статусом `answered`, текстом о Python и источником `setup`. Автотесты проверяют программные ограничения. Оценочный скрипт показывает отдельный результат на 14 видимых примерах; часть сложных случаев исходная версия не решает. Подробнее — [README лаборатории](../labs/knowledge-assistant/README.md).

## Разберите первую ошибку

Выполните:

```bash
python3 developers/labs/knowledge-assistant/assistant.py "кодовая инспекция"
```

В базе есть запись про review, но простой поиск не понимает все синонимы. Найдите случай `synonym-review` в `cases.json`. Подумайте, на каком этапе произошла ошибка: отсутствовал документ, не нашёлся документ или неверно составился ответ? Здесь документ существует, а поиск не связал слова запроса с записью. Более сильная модель на последней стадии не гарантирует исправления такого поиска.

Не исправляйте сразу все файлы. Сначала запишите одно предположение и способ проверки. Например: «Добавление нескольких терминов в метаданные улучшит поиск, но не покажет перенос на новые переформулировки». Это уже инженерное наблюдение.

## Что зафиксировать

Создайте личную заметку: версия Python; команда; результат тестов; один провал из eval; что хотите улучшить. Ключи и личные данные не нужны. Исходный отчёт сохранён как `baseline-results.json`; ваш результат должен воспроизводиться на той же версии кода.

**Готово**, если вы можете показать работающий запуск, объяснить разницу между тестами кода и оценкой ответа, назвать хотя бы одно ограничение baseline. Просто увидеть зелёный `OK` недостаточно для вывода, что система отвечает правильно на любые вопросы.

**Вопрос напарнику:** почему стенд без LLM уже полезен для обучения AI-разработке? Объясните через контрольную точку для сравнения.
