# 03. API модели: отделите генерацию от остального приложения

**Результат:** интерфейс модельного адаптера, проверки формата и ошибок; при доступном API — фактический запуск на синтетических данных. Без API выполните контрактные проверки с заглушкой и честно отметьте, что живой вызов не сделан.

## Что модель получает и что возвращает

Приложение отправляет запрос, инструкции и выбранный контекст. Ответ может быть обычным текстом, структурированным объектом или предложением вызвать инструмент. SDK, названия полей, роли сообщений и поддерживаемые схемы отличаются у провайдеров. Одинаковое название возможности не означает взаимозаменяемость одного JSON-запроса.

Выберите одного доступного провайдера по официальной документации: [OpenAI](https://developers.openai.com/api/docs/guides/function-calling), [Claude](https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview), [Gemini](https://ai.google.dev/gemini-api/docs/function-calling) или [ГигаЧат](https://developers.sber.ru/docs/ru/gigachat/guides/main). Доступ, действующие условия и стоимость проверяйте в своём аккаунте. Для этого задания не требуется покупать все сервисы.

## Спроектируйте адаптер

Внутренний интерфейс приложения может быть одинаковым независимо от SDK:

```python
# Схематический интерфейс: это НЕ готовый вызов API.
def generate_answer(question: str, snippets: list[dict]) -> dict:
    """Вернуть status, answer, sources либо поднять типизированную ошибку."""
    raise NotImplementedError
```

Отдельная реализация делает запрос выбранному провайдеру. Остальной код не должен знать его ключ, клиент SDK и формат сообщения. Это позволяет подменить адаптер для теста или сменить провайдера без переписывания retrieval.

Запишите в паспорт: SDK и его версию, модель, дату, режим структурированного ответа, timeout и лимит выходных токенов. Не угадывайте название модели по стилю ответа. Зафиксируйте именно то, что указано в конфигурации и ответе API.

## Структура не равна истинности

[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs) помогают получить согласованную форму. Но значение `answer` может быть неверным, а существующий ID может ссылаться на документ, который не подтверждает вывод.

Поэтому есть три уровня проверки:

1. Ответ завершён и нормально получен: нет transport error, обрыва или неподдержанного режима.
2. Объект соответствует вашему контракту: поля, типы, пределы, статусы.
3. Содержание соответствует данным: ответ подтверждён разрешёнными источниками.

В стенде `validate_answer` проверяет небольшой явный контракт и допустимость source IDs. Это не универсальный JSON Schema validator и не семантическая проверка. Не объявляйте первый или второй уровень доказательством третьего.

## Практика

Сначала создайте заглушку, возвращающую известный корректный объект. Затем последовательно подменяйте её результат: строка вместо объекта; лишнее поле; пустой список источников при `answered`; неизвестный ID; правильный ID с неправильным числом в тексте. Первые случаи должен отвергнуть код, последний должна обнаружить смысловая проверка.

После этого подключите выбранный API по его текущему quickstart. Ключ передаётся серверному/локальному процессу через переменную окружения или поддерживаемый менеджер секретов. Не вставляйте его в пример, публичный frontend, команду с историей или вывод тестов. Для эксперимента достаточно синтетического корпуса.

Сравните ответ с извлечением без модели на пяти одинаковых вопросах. Запишите, где модель улучшила понятность, где внесла неподтверждённые факты и где отказалась. Сохраните также ошибки, а не только лучший ответ.

## Обработка отказов

| Ситуация | Правильная инженерная реакция |
|---|---|
| Неверный ключ/права | Объяснимая конфигурационная ошибка, без бесконечных повторов |
| Rate limit | Ограниченная задержка и повтор с учётом общего deadline |
| Timeout | Отдельный технический статус; учёт уже потраченного бюджета |
| Невалидная структура | Отвергнуть либо выполнить ограниченную повторную попытку |
| Нет подтверждающих данных | `not_found` или уточнение по спецификации |
| Отказ модели | Обработать предусмотренный провайдером сигнал; не выдавать за успешный ответ |

Не устанавливайте бесконечный retry «до красивого JSON». Даже неуспешные попытки расходуют время и могут стоить денег.

**Готово:** адаптер можно заменить заглушкой, не меняя остальное приложение; ошибочные ответы не проходят молча; live-вызовы отдельно отмечены как выполненные или не выполненные.
