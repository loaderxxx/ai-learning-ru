# 08. A2A: когда отдельный агент действительно нужен

**Результат:** архитектурное решение с причинами. Дополнительная практика — взаимодействие с отдельным сервисом рецензирования по выбранной версии A2A. Модуль можно пройти без реализации второго агента.

## Функция, инструмент и самостоятельный сервис

Если нужно проверить JSON-схему, обычная функция часто решает задачу. Если внешний AI-клиент должен обнаружить и вызвать такую возможность, можно рассмотреть MCP. Если независимый сервис принимает задачу, ведёт её состояние и возвращает результат позже, может пригодиться A2A.

Это не лестница престижа. Несколько моделей не превращают систему в более качественную автоматически. У них появляются задержки, цена координации и новые ошибки: повтор задания, потеря статуса, несовпадение версии входного артефакта.

## Что читать в A2A

[Официальная спецификация](https://a2a-protocol.org/latest/specification/) описывает сведения об агенте, сообщения, задачи, состояния и артефакты. Agent Card сообщает возможности и параметры взаимодействия. Доверие к серверу, разрешение доступа и качество результата всё равно проверяются отдельно.

Ссылка `latest` изменяется. Выберите конкретную редакцию и поддерживающий её SDK. Точные имена полей и значения состояний берите из этой редакции, а не из похожего JSON в статье. В этом модуле используется смысловое описание, не обещание готового wire-совместимого шаблона.

## Сценарий для проектирования

В вашем учебном продукте появляется внешний сервис review. Он принимает идентификатор версии проекта и подготовленные синтетические результаты тестов. Он не получает пароль GitHub и доступ ко всем репозиториям. Через некоторое время возвращает артефакт: список замечаний с привязкой к критериям.

Разделите ответственность. Основное приложение создаёт запрос и показывает статус. Сервис review выполняет ограниченную задачу. Автор проекта принимает решение о правках. Рекомендация агента не должна автоматически запускать исправления и публикацию.

## Практика: сравните три варианта

| Вариант | Сложность | Когда его выбрать |
|---|---|---|
| Функция в одном процессе | Минимальная | Одна кодовая база, короткая детерминированная проверка |
| HTTP endpoint с описанием OpenAPI | Умеренная | Отдельный сервис с понятным API, не нужна агентная семантика |
| A2A | Выше | Нужны отдельные агенты, обнаружение возможностей и модель задач/артефактов |

Напишите решение на полстраницы. Если A2A не приносит конкретной пользы вашему проекту, обоснованный отказ от него — успешное выполнение обязательной части.

## Дополнительная реализация

Создайте два независимых процесса. Вместо LLM review сначала используйте детерминированный проверяющий, чтобы отладить протокол без вариативности текста. Затем при необходимости замените внутреннюю реализацию сервиса моделью.

Задайте сценарии: успешный результат; запрос дополнительного ввода; техническая ошибка; отмена ожидания; повтор сообщения; несовместимая версия; недоступный артефакт. Каждый запрос должен быть связан с конкретной версией входа. Замечание к commit А нельзя молча показывать как результат проверки commit Б.

Сохраните паспорт совместимости и фактический журнал. Не называйте собственный HTTP-сервис A2A-совместимым только потому, что у него есть поле `task_id`: это подтверждается требованиями выбранной спецификации и межоперационным тестом.

## Самые частые инженерные ловушки

Timeout клиента не означает, что сервер перестал работать. Отмена требует описанного поведения и подтверждения. Повтор запроса может породить вторую задачу, если не определены правила дедупликации. Публичный URL артефакта может раскрыть данные даже при корректной авторизации самого запроса. Поле роли в сообщении не заменяет подтверждённую идентичность отправителя.

Для нашего небольшого корпуса можно обойтись одной системой и MCP-инструментом. A2A изучается для понимания границ и совместимости, а не ради диаграммы с большим количеством агентов.

**Готово:** вы объяснили, кто за что отвечает, как версионируется вход и что происходит при сбое. Если выполнили дополнительную интеграцию — есть доказательства обмена, а не только схема.
