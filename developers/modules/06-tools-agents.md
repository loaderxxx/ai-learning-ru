# 06. Инструменты и агенты: модель предлагает, приложение проверяет

**Результат:** ограниченный цикл работы с двумя операциями чтения, явными остановками и негативными тестами. Сначала разберите `ToolSession` в лаборатории.

## Различайте три конструкции

Один вызов модели создаёт ответ. Workflow запускает известные шаги в заданном порядке. Агент может выбирать дальнейшие действия по промежуточным результатам. Термины используют по-разному, поэтому опишите реальное управление потоком, а не только напишите «агент» в README.

[Инженерная заметка Anthropic](https://www.anthropic.com/engineering/building-effective-agents) обсуждает эту разницу. Для учебной базы сначала достаточно фиксированного пути: найти документ → проверить → ответить. Динамический выбор инструмента добавляйте, если можете сформулировать его пользу и способ проверки.

## Вызов инструмента не исполняет себя

В обычном function calling модель формирует имя и аргументы. Приложение решает, допустимы ли они, запускает реализацию и возвращает результат. Формат обмена зависит от [провайдера](../SOURCES.md). Даже если JSON соответствует схеме, запрошенная операция может выходить за права пользователя.

В стенде доступны `search_docs(query)` и `get_doc(id)`. Нет операции «выполнить произвольную команду». ID не интерпретируется как путь к файлу. Неизвестные операции и лишние аргументы отвергаются. Бюджет относится к одному запросу и учитывает неудачные попытки.

## Первый разбор руками

Откройте Python из папки лаборатории:

```python
from assistant import ToolSession, load_documents
session = ToolSession(load_documents(), max_calls=2)
session.call("search_docs", {"query": "python версия"})
session.call("get_doc", {"id": "setup"})
```

Третий вызов той же сессии должен остановиться с `tool budget exhausted`. В новой сессии проверьте `get_doc` для `staff-demo`: запись не выдаётся. Проверьте неизвестное имя `run_shell`: вместо исполнения вы получите ошибку.

Это обычный локальный Python-код, не MCP-сервер и не автономная LLM-система. Его назначение — показать, где должны жить ограничения, прежде чем к ним подключат модель.

## Добавьте цикл

Схематический алгоритм:

```text
создать контекст запроса и бюджет
пока есть время и разрешённые шаги:
    получить от модели ответ или предложенный вызов
    если ответ: проверить контракт и завершить
    если вызов: проверить имя, аргументы, права и бюджет
    выполнить разрешённую функцию
    передать ограниченный результат модели
если лимит исчерпан: завершить с объяснимым отказом
```

Это алгоритм для реализации, а не готовый SDK-код. Общий deadline нужен дополнительно к количеству вызовов: один зависший инструмент может исчерпать всё время. У результата инструмента тоже должен быть лимит размера. Повторяющийся одинаковый вызов без новых данных может быть признаком зацикливания.

## Практическое задание

Сначала используйте сценарную заглушку вместо модели: первый ответ предлагает поиск, второй — чтение, третий — финальный объект. Затем создайте ошибочные сценарии: неизвестный инструмент, попытка доступа к служебной записи, лишний параметр `role`, бесконечные повторные вызовы, испорченный финальный объект.

После прохождения сценариев можно подключить реальную модель. В журнале отдельно отметьте: проверки orchestration с заглушкой; реальный tool calling; ограничение live-проверки. Заглушка помогает тестировать код, но не доказывает, что модель всегда будет вести себя так же.

## Почему запись сложнее чтения

При добавлении внешних действий появляется риск повтора. Сервер мог успешно создать запись, а клиент не получить ответ. Слепой retry создаст дубликат. Для операций записи нужен идентификатор запроса и серверная идемпотентность: повтор получает сохранённый результат исходной операции, а не выполняется заново.

В первом проекте достаточно операций чтения. Для расширения спроектируйте создание черновика, который человек просматривает перед отправкой. Не подключайте публикацию, платежи или административные действия только ради демонстрации автономности.

**Готово:** цикл останавливается предсказуемо, права проверяются кодом, сценарные ошибки покрыты, статус live-интеграции указан честно.
