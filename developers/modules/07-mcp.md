# 07. MCP: подключите небольшой инструмент и проверьте совместимость

**Результат:** реализация read-only инструмента в выбранном SDK, фактический вызов из клиента и [паспорт интеграции](../templates/INTEGRATION.md). В исходной лаборатории MCP-сервер не реализован: это ваша следующая работа.

## Зачем протокол, если функция уже работает

Локальная функция доступна только коду, который знает её интерфейс. MCP задаёт общий способ предоставлять инструменты и контекст совместимым приложениям. В модели взаимодействия есть host, клиент внутри него и сервер возможностей. Сервер может открыть поиск по учебным документам, не выдавая произвольный доступ к файловой системе.

Не путайте это с качеством реализации. Протокол помогает обмениваться сообщениями; корректность аргументов, права и реальные побочные эффекты остаются ответственностью приложения.

## Сначала зафиксируйте редакцию

При проверке 23.09.2026 официальный `latest` открыл [спецификацию 2026-07-28](https://modelcontextprotocol.io/specification/2026-07-28). Она отличается от старых руководств: в частности, описывает метаданные версии/возможностей для отдельных запросов и совместимость с более ранними session/initialize-подходами.

Поэтому не смешивайте пример из старого урока с новым SDK, не проверив поддерживаемую редакцию. Ваш клиент может поддерживать другую совместимую версию. В паспорте укажите именно проверенную комбинацию. Вводную архитектуру можно изучить сразу, а wire-детали — по выбранной редакции и её SDK.

## Выберите транспорт

| Вариант | Как обычно подключают | Что проверить |
|---|---|---|
| stdio | Клиент запускает локальный процесс сервера | Исполняемый файл, аргументы, окружение, протокольный stdout и журнал stderr |
| Streamable HTTP | Клиент обращается к endpoint сервера | Адрес, TLS для удалённого сервиса, авторизация, лимиты и доступность |

Подробности: [transport specification](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports). SSE — способ доставки потока событий/ответа в соответствующем transport, а не универсальное название MCP. Не считайте устаревший HTTP+SSE пример автоматически подходящим текущему серверу.

## Реализуйте только две возможности

Используйте официальную SDK-документацию, выбранную через [сайт MCP](https://modelcontextprotocol.io/). Закрепите фактическую версию зависимости в своём проекте. Не начинайте с ручной реализации всего JSON-RPC.

Предоставьте:

- `search_docs`: строка запроса, ограниченный список разрешённых результатов;
- `get_doc`: ID документа, содержимое только при разрешённом доступе.

Сохраните фильтр доступа внутри серверной реализации. Проверка только в UI недостаточна: клиент может обойти интерфейс и отправить запрос напрямую. Аргумент `id` должен сопоставляться с записью, а не преобразовываться в произвольный путь.

Опишите инструмент точно: что принимает, какие данные возвращает и как сообщает отсутствие документа. Не заявляйте «безопасен для любых данных» — это невозможно вывести из названия и описания.

## Проверьте интеграцию

Сначала запустите сервер локально и подключите один совместимый клиент или официальный инструмент проверки. Успех состоит не в появлении строки «connected», а в полном обмене:

1. Клиент видит ожидаемый инструмент и его схему.
2. Корректный запрос возвращает ожидаемую запись.
3. Неизвестный ID даёт нормальный результат отсутствия.
4. Служебная и архивная записи не выдаются.
5. Неверные/лишние аргументы отвергаются.
6. Журнал показывает ошибку без ключей и всего пользовательского контекста.

Сохраните версию клиента, сервера, SDK, команду и результат. Не публикуйте окружение с секретами. Если сервер не удалось соединить с клиентом, пишите «реализация подготовлена, совместимость не подтверждена», а не «MCP готов».

## Доступ и доверие

[Авторизация MCP](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization) описывает HTTP-сценарии. Токен должен быть предназначен правильному ресурсу; его нельзя бездумно пересылать следующему сервису. Для stdio действуют другие условия передачи credentials и полномочий локального процесса.

Даже read-only сервер способен раскрыть лишние данные. Ограничивайте корпус и возвращаемый объём. Описание инструмента и annotations не являются технической гарантией; [security guidance](https://modelcontextprotocol.io/docs/2026-07-28/tutorials/security/security_best_practices) стоит читать вместе со спецификацией.

**Готово:** напарник воспроизводит вызов вашей конкретной комбинацией версий, видит допустимый результат и отказ на недопустимый доступ. Нет требования подключать удалённый сервер или выдавать доступ ко всему компьютеру.
