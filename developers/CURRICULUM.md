# План обучения и критерии продвижения

Проходите маршрут по результатам, а не по числу прочитанных страниц. Все оценки времени ориентировочные. Итоговый проект может занять больше времени, особенно при изучении нового языка или API.

## Перед началом

Вы можете прочитать короткую функцию, запустить программу, понять изменение в Git и написать простую проверку. Если отдельный пункт вызывает трудность, запишите её в диагностике. Если все пункты незнакомы, сначала нужен базовый курс программирования: наш [начальный маршрут](../START_HERE.md) знакомит с ИИ, но не заменяет такой курс.

## Блоки и зависимости

| Блок | Модули | Нагрузка, оценка | Контрольная точка |
|---|---|---|---|
| Осмысленная разработка | 00–02 | 5–8 ч | Вы объясняете baseline, требования и одну правку |
| Модель и знания | 03–04 | 7–12 ч | Адаптер и поиск имеют отдельные проверки |
| Измерение и действия | 05–06 | 7–12 ч | Ошибки классифицированы, цикл ограничен |
| Совместимость | 07; 08 по желанию | 5–10 ч | Есть фактический журнал интеграции либо явно отмечен только дизайн |
| Доставка результата | 09–11 | 10–18 ч | Другой человек запускает проект и проверяет ограничения |

Без API-доступа можно выполнить 00–02, офлайн-части 04–06 и 09–11. Модельную генерацию нельзя в таком случае отметить выполненной. Вместо этого получится проверенный retrieval/tooling-стенд и подготовленный интерфейс модели. Это полезный промежуточный результат.

## Какие доказательства сохранять

Для каждого модуля достаточно короткой записи: задача → версия кода → что изменили → как проверили → результат → ограничение. Не сохраняйте весь чат с ИИ ради объёма. Пример оформления есть в [шаблоне эксперимента](templates/EXPERIMENT.md).

| Уровень | Что означает | Как подтвердить |
|---|---|---|
| Прочитано | Можете пересказать идею | Два предложения своими словами |
| Воспроизведено | Пример работает в вашей среде | Команда, версия, результат |
| Применено | Изменили условие и сохранили нужное поведение | Новый случай и проверка |
| Объяснено | Другой человек понял ваше решение | Вопросы и запись review |

Оценка не является дипломом. Не переходите от одного запуска к заявлению «готов к промышленной эксплуатации».

## Как выбирать тему по роли

Backend-разработчику обычно удобно начать с контракта, API, ошибок и бюджета. Frontend-разработчику — с состояний интерфейса, потокового ответа, отмены и источников. QA-инженеру — с разметки, различения случайного изменения и регрессии, негативных сценариев. Системному программисту — с процесса инструмента, транспорта, файловых разрешений и границ выполнения. Это рекомендации для выбора входа, а не рейтинг профессий.

## Выпуск проекта

Обязательный минимум: запуск из чистой папки, понятное поведение при отсутствии ответа, отсутствие доступа к запрещённым записям, проверки входов/выходов, результаты на отложенных случаях, описание использованного ИИ. Модельный вариант дополнительно требует фактического API-запуска и сравнения с baseline. MCP/A2A — отдельные расширения с собственными доказательствами.
